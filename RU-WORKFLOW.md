# Русификация Hermes Desktop — workflow (пошаговый промпт для LLM)

Цель: при каждом обновлении Hermes довести русскую локализацию до состояния
«переведено всё осмысленное, `ru.ts` идёт построчно как `en.ts`, сборка проходит».

Корень установки: `D:\NEURO\Hermes`. Источник переводов: `scripts\ru-locale\ru.ts`.

---

## Модель файла

`ru.ts` — **зеркало** `en.ts`: тот же набор ключей, тот же порядок, та же разметка строк,
перевод там, где он есть, английский текст там, где перевода ещё нет.

- Совпадающие строки `en.ts` ↔ `ru.ts` = **не переведено** (или бренд/URL — их переводить не надо).
- Различающиеся строки = переведено.
То же правило для **`ru-constants.ts`** (`RU_FIELD_LABELS` / `RU_FIELD_DESCRIPTIONS`):
зеркало `srcpp\settings\constants.ts` — те же ключи, тот же порядок, перевод или англ. текст.
Если ключа нет, подпись поля в UI остаётся английской (а тест `settings-i18n.test.tsx`
требует отличия от en), поэтому за полноту отвечает `i18n_mirror_constants.py`.

- Особенности `ru.ts` (не совпадают с en — это нормально):
  - **шапка (4 строки)**: два импорта, пустая строка, `export const ru = defineLocale({`;
  - **последняя строка**: `})`.
- Из-за шапки все строки тела смещены на **−1** относительно en — сдвиг постоянный
  (не накопительный), WinMerge выравнивает по якорям секций.

---

## Инварианты (нарушение = сломанный Desktop)

1. Шапка и хвост остаются как выше (defineLocale + RU_FIELD_* + `})`).
2. `ru.ts` не пересоздаётся «руками»: тело берётся из `en.ts`, значения подставляются.
3. **Существующие переводы неприкосновенны.** Меняем только при явном смысловом
   расхождении и с подтверждением владельца. Импорт не перезаписывает строку,
   если текст совпадает.
4. TS-приведения (`} as Record<string, string>,`), функции (`count => ...`), массивы и
   шаблонные строки переносятся как есть.
5. Ключи с дефисом — в кавычках (`'local-runtime-update': {...}`).
6. Плоский стиль группы сохраняется (`'view.toggleHud'` и т.п.).

## Шаги

**0. Предусловие.** `scripts\en-locale\en.ts` — актуальная копия из репозитория Hermes
(`scripts\InstallOrUpdate-RU.bat` шаг 2 или `Rebuild-Desktop.bat`).

**1. Отчёт: что переводить.**
```
python scripts\py\i18n_verify.py                      # сводка: кандидаты на перевод, осиротевшие
python scripts\py\compare_i18n_keys.py --same         # список строк, где текст совпал с английским
python scripts\py\compare_i18n_keys.py --flatten data\temp\i18n-compare
```
`--flatten` даёт `en.flat`/`ru.flat` — **построчно 1:1, порядок как в en.ts**,
`<НЕТ ПЕРЕВОДА>` для отсутствующих ключей; удобно смотреть в WinMerge (Tools.bat `[1]`).

**2. Перевод (LLM пошагово).** Переводить только кандидатов из шага 1
(текст = английский). Бренды, аббревиатуры и URL не трогать.
Результат — файл `ключ = русский текст` (одна строка на ключ; переносы — литерально).

**3. Импорт в источник.**
```
python scripts\py\i18n_apply_flat.py --flat <файл> --ru scripts\ru-locale\ru.ts
```
Выводится список «Изменённые переводы» — проверить, что меняется только задуманное.
Делается `.bak`.

**4. Зеркало: полнота + порядок + построчность.**
```
python scripts\py\i18n_mirror.py          # или Tools.bat [9]
```
Тело берётся из `en.ts` (новые ключи появляются автоматически с английским текстом),
значения подставляются из текущего `ru.ts`. Ожидаем строку
«построчность: … сдвиг после шапки: −1» и постоянный сдвиг (без накопления).
Копия — `ru.ts.pre-mirror`.

**4b. Зеркало констант (подписи полей настроек).**
```
python scripts\py\i18n_mirror_constants.py
```
Ожидаем «переводов сохранено: N, добавлено из en: M» и «ключей: labels …, descriptions …».
Новые подписи приходят с английским текстом — их переводим тем же порядком (шаги 2-3),
правя `scriptsu-localeu-constants.ts`.

**5. Проверка (ядро workflow).**
```
python scripts\py\i18n_verify.py          # или Tools.bat [8]
```
Структура (ключи, нет мусорных ключей) + **esbuild-синтаксис** `ru.ts` и `ru-constants.ts`
+ порядок как в en + сводка. Нужен «ИТОГ: проверка пройдена» (exit 0).

**6. Сборка.**
`scripts\Tools.bat` → `[5]`: бэкап (файлы локализации + готовая сборка) → **esbuild-проверка** →
`Rebuild-Desktop.bat` (копирует `ru.ts` в `i18n\`, патчит `types/languages/catalog`,
`npm install` + `npm run pack`) → запуск Desktop.
При сбое — `Tools.bat` → `[6]`: откат файлов и сборки из `data\backup\` (без пересборки).

**7. Цикл.** Если `verify` или сборка не прошли — правим и повторяем с шага 3,
пока `i18n_verify.py` не вернёт exit 0, а сборка не завершится успешно.

---

## Критерии готовности

- `i18n_verify.py` → exit 0: структура, esbuild, порядок, **и `[5/5] ru-constants` без пропусков**.
- Построчность: сдвиг строк относительно en постоянный (−1 из-за шапки), без накопления.
- Кандидатами на перевод остаются только бренды/аббревиатуры/URL (и пустые в en).
- `Tools.bat [5]` → сборка успешна, Desktop запускается, UI на русском.

## Откат (если «котяха»)

- `Tools.bat [6]` — файлы локализации + собранный Desktop из `data\backup\`.
- Копии: `ru.ts.bak` (до импорта), `ru.ts.pre-mirror` (до зеркалирования), `ru.ts.pre-sort`.

## Инструменты (`scripts\py\`)

| Скрипт | Назначение |
|---|---|
| `i18n_verify.py` | проверка: структура + esbuild + порядок + сводка (exit 1 = не собирать) |
| `i18n_mirror.py` | ru.ts как зеркало en.ts: полнота, порядок, построчность |
| `i18n_mirror_constants.py` | ru-constants.ts как зеркало constants.ts (подписи/описания полей) |
| `compare_i18n_keys.py` | отчёт en/ru: кандидаты (`--same`), осиротевшие, `--flatten` (выровненная пара) |
| `i18n_apply_flat.py` | импорт переводов в ru.ts (`--only-new`, `--prune`, `--dry-run`, `--out`) |
| `i18n_sort_like_en.py` | выравнивание порядка без заполнения пропусков (legacy-режим) |
| `ru_locale_backup.py` | бэкап/откат (файлы + сборка) |

## Пункты Tools.bat

`[1]` сравнение ключей (WinMerge, выровненные списки) · `[2]` сравнение исходников en.ts/ru.ts ·
`[3]` .env · `[4]` config.yaml · `[5]` пересборка с бэкапом · `[6]` откат · `[7]` очистка репозитория ·
`[8]` проверка русификации · `[9]` зеркало ru.ts
