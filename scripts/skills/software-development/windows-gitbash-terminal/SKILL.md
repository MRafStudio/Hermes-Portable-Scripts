# Windows git-bash / MSYS terminal usage

Работа в `terminal` на Windows-хосте идёт через **git-bash (MSYS)**, а не PowerShell/cmd. Это накладывает жёсткие правила на пути и файловые операции.

## Критические правила путей (выучено на ошибках)

1. **Обратный слеш `\` в bash — escape-символ.** Windows-путь `D:\NEURO\Hermes\data\home` внутри команды bash **молча превращается** в `D:NEUROHermesdatahome` (слеши «съедаются»), команда работает с мусорным путём, а `ls` выдаёт `cannot access 'D:NEUROHermesdatahome': No such file or directory`.
2. **Правильные формы пути в git-bash:**
   - Прямые слеши: `D:/NEURO/Hermes/data/home/Projects`
   - MSYS-стиль: `/d/NEURO/Hermes/data/home/Projects`
   - Одинарные кавычки вокруг Windows-пути: `'D:\NEURO\Hermes\data\home\Projects'`
3. **`rm -rf` с флагом `-f` на несуществующем пути молча возвращает exit 0** — команда «успешна», но ничего не удалила. НИКОГДА не верь exit code одинокого `rm -rf -f`: после удаления/очистки **обязательно проверять результат** (`ls -la <путь>`), иначе будешь рапортовать «готово» при нетронутом каталоге.
4. **Очистка содержимого каталога** (включая скрытые файлы, `*` их не ловит):
   ```bash
   find /d/NEURO/Hermes/data/home/Projects -mindepth 1 -delete && ls -la /d/NEURO/Hermes/data/home/Projects
   ```
   Сам каталог остаётся на месте; `find -delete` надёжнее glob `*`.
5. **В тексте ответов пользователю Windows-пути писать С ОДИНАРНЫМИ слешами** (`D:\NEURO\Hermes\...`), никогда с двойными (`D:\\NEURO\\...`). Двойные слеши пользователь считает ошибкой и раздражается — даже в markdown-ответах, где они «экранированные».
6. **Не зацикливаться:** если команда не сработала (путь не найден, блокировка, каталог не очистился) — НЕ повторять ту же команду в цикле. Остановиться, проанализировать (обычно причина: съеденные bash'ем обратные слеши или скрытые dot-файлы, которых не ловит `*`), попробовать другой подход и проверять результат `ls -la` после каждой попытки. Пользователь прямо требует: «Пробуй разные варианты! Не тупи, если один не проходит!»

## Конвенции пользователя (обязательны)

- **Все репозитории, клонируемые с GitHub, класть ТОЛЬКО в `D:\NEURO\Hermes\data\home\Projects`**, каждый в свой подкаталог `<имя_репо>` — никогда не смешивать файлы в корне Projects и никогда не клонировать в другие места (в т.ч. в корень `data/home`).
- **Не трогать содержимое `D:\NEURO\Hermes\data\home`** — это рабочий домашний каталог Hermes; там живут AppData и прочее. Манипуляции допустимы только внутри `Projects`.
- **Деструктивные операции (удаление, очистка, перемещение): сначала спросить/озвучить план**, дождаться подтверждения понимания — пользователь сам скажет «выполняй».
- Пользователь ждёт, что агент сам предлагает закрепить важные правила в памяти/скиллах, а не ждёт просьбы.

## Диагностика

- `pwd` показывает MSYS-путь (напр. `/d/NEURO/Hermes/data/home`) — это нормальный рабочий каталог сессии.
- Ошибка вида `cannot access 'D:NEUROHermesdatahome'` = обратные слеши съедены bash'ем. Исправить путь (см. выше), а не менять команду.
- Если `ls` по абсолютному пути падает, а относительный работает — почти всегда проблема слешей.

## Связанные quirks (кратко)

- `write_file` пишет `.bat` с LF — конвертить в CRLF перед запуском через cmd.
- `cmd //c script.bat` из MSYS не работает — запускать `./script.bat` из каталога.
- curl с кириллицей в `-d`/URL — писать JSON в файл и слать `--data-binary @file`.
- `taskkill //F` не работает — `powershell Stop-Process -Id N -Force`.

Подробный разбор симптома и рабочая последовательность — в `references/msys-backslash-debug.md`.
