# Русификация Hermes Portable (ru.ts)

Актуально для портабельной установки (`D:\NEURO\Hermes`): источник переводов — `scripts\ru-locale\ru.ts`, UI собирается локально из репозитория Hermes.

## Архитектура i18n (новая, ~v0.20+)

- `apps/desktop/src/i18n/en.ts` — **эталон**, полный словарь: `export const en: Translations = {...}`.
- `ru.ts` (как ja/zh/ar) — **оверрайды**: `export const ru = defineLocale({...})`, где `defineLocale(overrides) => mergeTranslations<Translations>(en, overrides)`.
- Поэтому построчный WinMerge `en.ts` ↔ `ru.ts` даёт шум (разные обёртки/порядок секций). Правильное сравнение — по **ключам**.
- Регистрация: `i18n/catalog.ts` (TRANSLATIONS), `i18n/languages.ts` (LOCALE_OPTIONS), `i18n/types.ts` (Locale), `app/settings/constants.ts` и `ru-constants.ts` (FIELD_LABELS / FIELD_DESCRIPTIONS).

## Источник правды и применение

- Редактируется **`scripts\ru-locale\ru.ts`** (+ `ru-constants.ts`). Именно их копирует сборщик:
  `Rebuild-Desktop.bat` шаг 2 → `apps\desktop\src\i18n\ru.ts` и `src\app\settings\ru-constants.ts`; шаг 3 — патчи `types/languages/catalog` (`scripts\ps1\patch_*.ps1`) + `hermes config set display.language ru`; шаг 4 — `npm install` + `npm run pack`.
- `InstallOrUpdate-RU.bat` делает то же копирование отдельно.
- Правки в ru-locale без пересборки в UI не появятся.
- Tools.bat: [1] сравнение ключей (flat), [2] прямое сравнение исходников, [5] пересборка с бэкапом, [6] откат, [8] проверка (5/5), [9] зеркало ru.ts, [10] полный цикл русификации.

## Официальный русский в Hermes и наше соотношение (сверено с GitHub)

- В апстриме `NousResearch/hermes-agent` (ветка main) русский **есть**: `apps/desktop/src/i18n/ru.ts`
  (~258 КБ) + регистрация в `types.ts` / `languages.ts` / `catalog.ts` + **русская плюрализация**
  (`RU_PLURAL`/`RU_NOUN`, формы один/два/пять, ~63 использования).
- Но их перевод **неполный**: ~704 ключа отсутствуют (больше всего settings, skills, tips, prompts,
  sendDiagnostics) - эти места UI берутся из en.
- Наш `scripts\ru-locale\ru.ts` полнее: 0 отсутствующих ключей, но ~150 значений ещё английским
  текстом; плюрализации нет (двухформенные заглушки `count === 1 ? ... : ...`).
- **Решение владельца: в апстрим ничего не предлагать** (ни issue, ни PR - откажут) и плюрализацию
  пока не переносить: живём своим workflow, к вопросу вернуться, если апстрим быстро доберёт ключи.
- Следствие: при обновлении Hermes апстримный `ru.ts` перезаписывается нашим (шаг 2 сборщика), их
  улучшения сами не подтягиваются. Сравнить при нужде:
  `git -C data/hermes/hermes-agent show HEAD:apps/desktop/src/i18n/ru.ts > data/temp/upstream-ru.ts`,
  затем `python scripts\py\compare_i18n_keys.py --en scripts\en-locale\en.ts --ru data/temp/upstream-ru.ts`.

## Инструменты (scripts\py\, запуск питоном репозитория)

Питон: `data\hermes\hermes-agent\venv\Scripts\python.exe` (иначе системный `python`).

- `compare_i18n_keys.py` — ключи en vs ru: непереведённые / осиротевшие / идентичные. Флаги: `--text`, `--same`, `--limit N`, `--json`, `--flatten DIR`.
  `--flatten` пишет `en.flat` / `ru.flat` / `missing.flat`: **порядок ключей как в en.ts, построчно 1:1**, отсутствующие в ru — `<НЕТ ПЕРЕВОДА>` (в WinMerge сразу виден каждый пропуск). Правки в .flat сами не применяются — их переносит `i18n_apply_flat.py`.
- `i18n_sort_like_en.py` — приводит порядок ключей и секций `ru.ts` к порядку `en.ts`: переносит фрагменты как есть (значения/функции/массивы не пересоздаются), проверяет идентичность содержимого, пишет копию `.pre-sort`. Нужен, чтобы WinMerge читался строка-в-строку.
- `i18n_apply_flat.py` — переносит переводы в ru.ts: `--flat FILE --ru PATH [--en PATH] [--prune] [--dry-run] [--out FILE]`. Меняет только строки/шаблоны (функции и ссылки не трогает), добавляет новые ключи и секции, `--prune` удаляет лишь однострочные осиротевшие ключи.
- `ru_locale_backup.py` — `backup | restore | status`: 7 файлов локализации в `data\backup\ru-locale\` + сборка переименованием `release` → `data\backup\desktop-release`.

## Модель файла (важно)

`ru.ts` — **зеркало** `en.ts`: тот же набор ключей, тот же порядок, та же разметка строк;
перевод там, где он есть, английский текст там, где перевода ещё нет. Совпадающие строки = не переведено
(или бренд/URL). Особенности `ru.ts`: шапка 4 строки (`defineLocale` + `RU_FIELD_*`, пустая строка)
и последняя строка `})` — из-за этого постоянный сдвиг всех строк тела −1 (не накопительный).
Ключи/порядок/полноту даёт `i18n_mirror.py` (тело берёт из en.ts), проверяет `i18n_verify.py`.

Подписи и описания полей настроек — в `ru-constants.ts` (`RU_FIELD_LABELS` / `RU_FIELD_DESCRIPTIONS`),
их источник `apps/desktop/src/app/settings/constants.ts`. Их тоже держим зеркалом:
`i18n_mirror_constants.py` (иначе подписи остаются английскими, а `settings-i18n.test.tsx`
ждёт отличия от en). Проверка — `i18n_verify.py` блок `[5/5]`.

Полный пошаговый промпт для LLM: **`RU-WORKFLOW.md` в корне репозитория** (модель, инварианты,
7 шагов, критерии, откат, таблица инструментов и пунктов Tools.bat).

## Workflow: обновление локализации под новую версию Hermes

Все команды — из корня `D:\NEURO\Hermes`:

1. **Обновить en.ts**: `scripts\InstallOrUpdate-RU.bat` (или сразу `Rebuild-Desktop.bat`).
2. **Выровненная пара для перевода** (1:1, порядок как в en.ts):
   `python scripts\py\compare_i18n_keys.py --flatten data/temp/i18n-compare`
   Результат в `data\temp\i18n-compare\`: `en.flat`, `ru.flat` (одинаковое число строк),
   `missing.flat` (готовый список непереведённого). В WinMerge: `en.flat` ↔ `ru.flat`.
3. **Перевод**: заполнить файл `ключ = русский текст` (одна строка на ключ; переносы внутри
   текста писать литерально двумя символами: backslash + n).
4. **Применить в источник**: `python scripts\py\i18n_apply_flat.py --flat ru.new.flat --ru scripts\ru-locale\ru.ts --en scripts\en-locale\en.ts --prune`
   (заменяет существующие, добавляет новые, чистит однострочных мёртвых, делает `.bak`).
5. **Выровнять порядок**: `python scripts\py\i18n_sort_like_en.py`
   (ждём строку «Проверка пройдена: ключей N (до и после идентичны)»).
5. **Зеркало (полнота + порядок + построчность)**: `python scripts\py\i18n_mirror.py`
   (Tools.bat [9]) — новые ключи приходят из en с английским текстом, копия `.pre-mirror`.
6. **Проверить и собрать**: `python scripts\py\i18n_verify.py` (Tools.bat [8]) — структура +
   esbuild + порядок; затем `Tools.bat [5]` (бэкап + esbuild + сборка), при сбое — `Tools.bat [6]`.
7. **Одной кнопкой**: `Tools.bat [10]` → `scripts\py\ru_workflow.py` прогоняет шаги 1-6 сам
   (эталоны → зеркало ru.ts → зеркало констант → регистрация → проверка → копирование в репозиторий
   → тестовая сборка Electron) и в конце спрашивает про боевую пересборку release.

Эталоны лежат в репозитории скриптов: `scripts\en-locale\en.ts` и `scripts\en-locale\en-constants.ts`
(их обновляет `InstallOrUpdate-RU.bat`, шаг 2/4).

## Стиль перевода (единый - сверяться не нужно)

Обращение: нейтральное «вы» («Ваш бэкенд», «Повторите», «освободите место»). Императив мягкий, без «пожалуйста».

Терминология (единообразно во всех строках):

| en | ru |
|---|---|
| backend | бэкенд |
| gateway | шлюз |
| skills | скиллы |
| sessions | сессии |
| profiles | профили |
| plugins | плагины |
| endpoint | эндпоинт |
| tools / toolset | инструменты / набор инструментов |
| subagents | субагенты |
| approvals | подтверждения |
| checkpoints | контрольные точки |
| attachments | вложения |
| draft | черновик |
| shortcut | сочетание клавиш |
| thread | беседа |
| timeline | таймлайн |
| provider | провайдер |
| vault | пароли и входы (раздел) / сохранённые учётные данные |
| desktop | дэсктоп / десктопная сборка |
| retry / undo | Повторить / Отменить |

Без перевода: Hermes, OpenAI, GitHub, Git, SSH, MCP-сервер, macOS/Mac, URL, API-ключ,
названия клавиш (Command), бренды и технические идентификаторы.

Оформление:
- Длинное тире «—» в НОВЫХ строках не ставим - только дефис «-» (вкус владельца). Существующие строки с «—» не переписываем.
- Многоточие одним символом «…».
- Заголовки подстраниц - существительными («Внешний вид», «Тема», «Окно и компоновка»).
- Цепочки меню - через «→» как в оригинале.
- Секунды - «(с)», не «(сек)». Эмодзи не добавляем.
- Кавычки - «ёлочки», внутри них кавычек не плодим.

## Скилл живёт в ДВУХ местах (обновлять оба!)

- Канон, попадает в git проекта: `scripts\skills\localization\hermes-portable-ru-locale\SKILL.md`
- Рабочая копия Hermes: `data\hermes\skills\localization\hermes-portable-ru-locale\SKILL.md`

Любая правка скилла = запись в оба файла. Направление деплоя одностороннее:
`InstallOrUpdate-Desktop.bat` / `InstallOrUpdate-Web.bat` копируют `%SCRIPTS_DIR%\skills` ->
`%HERMES_HOME%\skills` (robocopy /E /XO), обратно - никогда.

### Правила
- **Существующие переводы неприкосновенны**: LLM правит только отсутствующие ключи (импорт с `--only-new`); уже переведённое меняется лишь при явном смысловом расхождении и по согласованию с владельцем. Совпадающие строки импорт вообще не перезаписывает.
- Семантику (соответствует ли перевод смыслу) решает **LLM пошагово**, питон даёт только список кандидатов (`compare_i18n_keys.py --same` — ключи с одинаковым текстом en/ru).
- `ru.ts` — оверрайды: непереведённые берут английский из en автоматически, поэтому **пустые в en переводить не нужно**.
- Функции-значения (`count => ...`) при отсутствии в ru дают английский текст. Чтобы перевести — скопировать функцию в ru и перевести строку внутри.
- Ключи с дефисом — только в кавычках; импорт это делает сам.
- Порядок ключей на сборку не влияет (merge по ключам), но нужен для WinMerge — держать как в en.
- Валидность без полной сборки: `ast.parse` изменённых скриптов + прогон компаратора (сломанная структура видна как падение числа ключей).

## Грабли

- **`Rebuild-Desktop.bat` перед сборкой делает `rmdir /s /q release`**: при сбое `npm run pack` рабочего Hermes.exe не остаётся. Всегда сначала бэкап ([5]), откат — [6].
- Переименовать `release` при запущенном Hermes нельзя (WinError 5) — бэкап сборки только с закрытым Hermes; [5] предлагает закрыть.
- flat lossless: `\` → `\\`, перенос → `\n`, таб → `\t`; хвостовые пробелы в тексте значимы.
- Ключи с дефисом (`local-runtime-update`) в TS — только в кавычках (см. `ts_key` в i18n_apply_flat.py).
- В .bat скобки в `echo` внутри блока `if ( ... )` ломают парсер (`: was unexpected at this time`) — экранировать `^(` `^)`.
- Правки .bat с путями — через Python-фиксер, где backslash это `chr(92)` (маркер §BS§): прямая вставка `\r`/`\t` в payload превращается в CR/TAB и рвёт файл.
- **Никогда не править .bat через heredoc** (`python - <<'EOF'`): двойные бэкслеши становятся одинарными, `\r`/`\v` в путях превращаются в CR/VT, файл ломается незаметно. Только отдельный .py-файл (write_file) + `python file.py`; перевод строки — `NL = chr(13)+chr(10)`.
- `.ps1` с кириллицей (например, алиасы `русский`) обязан быть в **UTF-8 с BOM**, иначе PS 5.1 читает его как cp1251 и вставит мусор. Целевые `.ts` при этом пишутся **без BOM** (`New-Object System.Text.UTF8Encoding($false)`).
- Проверка патчеров регистрации языка: `python scripts\py\check_ps1_patchers.py` — сверяет вставку на «состаренной» копии (exit 0) и идемпотентность на актуальной (exit 1), результат должен бит-в-бит совпасть с оригиналом.
